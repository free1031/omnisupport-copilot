Northstar Workspace administrator access recovery

Document owner: Identity Operations. Version 4.2. Effective 2026-06-15.

When to use this runbook

Use this procedure when an administrator enters an SSO login loop, sees repeated sign-in redirects, or loses access after an identity-provider certificate rotation. This runbook applies to Northstar Workspace 4.1 and 4.2.

如何恢复 Workspace 管理员访问：先确认至少一名 break-glass owner 仍可登录，再核对身份提供商元数据和证书指纹。不要直接删除组织或重置全体成员。

Recovery procedure

  1. Open the organization audit log and confirm the last successful administrator login.
  2. Compare the IdP signing certificate fingerprint with the active Workspace SSO configuration.
  3. If the certificate changed, upload the renewed metadata file and validate it without activating.
  4. Ask a second administrator to review the organization identifier and redirect URL.
  5. Activate the validated metadata, invalidate stale authorization sessions, and start a new browser session.
  6. Verify two administrator accounts and record the change ticket before closing the incident.

Evidence and rollback

Capture the previous certificate fingerprint, the new fingerprint, validation result, reviewer, and change ticket. If validation fails, restore the previous metadata snapshot. Never paste private keys or session tokens into a support ticket.

Error reference

WS-AUTH-001 means the SSO assertion could not be validated. WS-PERM-002 means the session contains stale role claims. Refreshing metadata addresses WS-AUTH-001; invalidating the authorization cache addresses WS-PERM-002.
